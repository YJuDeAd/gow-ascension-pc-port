# Plan 11-01: Live WASAPI 8-Channel Audio Output & Block Read Index Cadence Verification

## Goal
Verify that the `cellAudio` mixing thread initializes Windows WASAPI, processes 8-channel float blocks at 48 kHz (256 samples @ 5.33 ms cadence), downmixes 7.1 surround sound to stereo float, and advances the audio block read index (`CELL_AUDIO_BLOCK_8`) without buffer underruns or audio stalls.

---

## Task 1: Enable Audio Diagnostics in Runner
- Update `tools/run_port.ps1` to configure:
  - `$env:AUDIO_RATE = "1"` (reports real-time mixing rate vs 187.5 blocks/s, buffer status, dropped frames)
  - `$env:AUDIO_PEAK = "1"` (reports block peak amplitude and ring buffer occupancy)
- Verify `tools/run_port.ps1` contains the audio diagnostic environment flags.

### Verify Command
```powershell
Select-String -Path tools\run_port.ps1 -Pattern "AUDIO_RATE|AUDIO_PEAK"
```

---

## Task 2: Live WASAPI Audio Stream & Cadence Verification
- Launch the port with LiveDraw and audio diagnostics enabled:
  `tools/run_port.ps1 -LiveDraw -TimeoutSeconds 30`
- Inspect `build/run_port_stderr.log` and `build/run_port_stdout.log` to verify:
  1. `[cellAudio] Mixing thread started` is logged.
  2. `[cellAudio]` port creation/configuration messages or `[audio-rate]` metrics confirm blocks are mixed at ~187.5 blocks/sec.
  3. No buffer stalls or audio driver failures occur.

### Verify Command
```powershell
Select-String -Path build\run_port_stdout.log,build\run_port_stderr.log -Pattern "cellAudio|audio-rate|audio-peak" | Select-Object -First 20
```
