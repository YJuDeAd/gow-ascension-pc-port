<decisions>
## Implementation Decisions

### 1. RSX-to-D3D12 Bridge Architecture (`RSX_LIVE_DRAW`)
- Query analysis of `ps3recomp/runtime` and `twistedmetal/docs/first-pixels.md` confirms:
  - `cellGcmSys.c` serves as the front-end RSX FIFO command parser, translating method packets into NV4097 state.
  - When `$env:RSX_LIVE_DRAW = "1"` is active, `cellGcm_rsx_process_fifo()` forwards NV4097 methods to `rsx_live_draw_method()`.
  - `rsx_live_draw.c` provides the live D3D12 engine: dynamically compiling guest NV40 VP/FP microcode into HLSL, caching PSOs, decoding vertex buffers directly from guest memory via `gow_live_guest_ptr`, and presenting to a DXGI swapchain bound to the game's Win32 window.
  - Flip requests (`cellGcmSetFlipCommand` and `_cellGcmSetFlipCommandWithWaitLabel`) queue flip markers into the FIFO and route to `sink_flip()` -> `rsx_live_draw_present(buffer_id)`.

### 2. Dedicated Launch Profile in `tools/run_port.ps1`
- Add a `-LiveDraw` profile switch to `tools/run_port.ps1` that configures the complete RSX diagnostic environment:
  - `$env:RSX_LIVE_DRAW = "1"`: activates the D3D12 live rendering pipeline.
  - `$env:GCM_RECDBG = "1"`: records the last RSX FIFO commands and decode chains for diagnostic post-mortems on mis-decoded jumps.
  - `$env:GCM_REFLOG = "1"`: logs reference marker and fence updates.
  - `$env:LD_TRACE_PSO = "1"`: traces pipeline state object compilation and constant uploads.
  - `$env:GCM_SEMA_ACQUIRE = "0"`: prevents blocking semaphore stalls from deadlocking the FIFO walker while permitting `RELEASE` writes to unblock the guest.

### 3. Mitigating the SPURS-to-RSX Label Deadlock Bottleneck
- **The Bottleneck:** Santa Monica Studio's rendering pipeline relies heavily on SPURS workloads (`libedgegeom`, mesh processing, and deferred lighting) that write completion values to RSX label addresses (`cellGcmGetLabelAddress`). The RSX command stream contains semaphore acquire commands (`NV406E_SEMAPHORE_ACQUIRE` / `0x0068`) waiting for those labels before drawing geometry. If an SPU workload has not yet completed or has not updated the label, a blocking RSX walker hangs indefinitely, freezing the render thread.
- **Resolution Strategy:**
  1. Keep `GCM_SEMA_ACQUIRE=0` as the baseline safe mode during initial bring-up so the walker does not wedge on unfinished SPU passes, while ensuring all `SEMAPHORE_RELEASE` (0x006C) commands reliably write their values to guest label memory (`GCM_LABEL_GUEST_BASE + offset`).
  2. Implement an RSX label monitor in `src/compat/ascension_hle.cpp` to track label addresses requested by `cellGcmGetLabelAddress` and log guest vs host synchronization points.
  3. Wire a watchdog mechanism in the FIFO pump: if `get` stalls on an unwritten label while `put` has advanced, auto-satisfy the label condition or advance `get` to prevent permanent render freeze.

### 4. Phase 5 Plan Structure
The phase is broken into three atomic plans:
1. **Plan 05-01 (D3D12 Window, IO Mappings & Swapchain Presentation):**
   - Wire Win32 window creation and message pump in `main.cpp`.
   - Verify GCM IO memory mapping capacity using `test_gcm_io_mappings.py` and `test_gcm_map_flags.py`.
   - Connect `cellGcmSetFlipCommand` to the D3D12 swapchain and verify initial clears and buffer presentation.
2. **Plan 05-02 (RSX Label/Semaphore Synchronization & SPURS Unblock):**
   - Audit label addresses generated by `cellGcmGetLabelAddress`.
   - Validate NV406E semaphore methods (`0x64 OFFSET`, `0x68 ACQUIRE`, `0x6C RELEASE`).
   - Implement watchdog/auto-advance logic to eliminate deadlocks between SPURS jobs and RSX command execution, verifying continuous frame flips.
3. **Plan 05-03 (Shader Translation, 2D Boot Logos & UI Presentation):**
   - Audit VP/FP decompiler output using `vp_eval.py` and `validate_vp_shaders.c`.
   - Resolve shader compilation errors (HLSL semantics, constant registers, texture samplers).
   - Verify visible 2D boot screens, loading animation, and menu UI rendering on screen.
</decisions>
