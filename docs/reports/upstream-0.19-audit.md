## 1. Executive Summary

When updating `ps3recomp` to upstream commit `8c50d9ea` (v0.19.0 base) in commit `85a66895`, God of War: Ascension suffered a complete boot failure and black screen regression. The title hung during early boot without displaying introductory logos or rendering 3D graphics. In commit `c6b3d14d`, the submodule was restored to local commit `9562c751`, instantly recovering logo playback and rendering.

This audit provides an exhaustive comparison between our pinned tree (`9562c751`) and upstream `v0.19.0` (`ae92407b` / `8c50d9ea`). The investigation reveals three primary root causes for the regression:
1. **Total Absence of Edge Zlib Host Decompression (HLE):** Upstream `v0.19.0` completely lacks `libs/codec/edge_inflate.cpp` and does not implement `_cellSpursLFQueuePushBody` (NID `0x8A85674D`). In GoW:A, all archive streams from `GAME.PSARC` and chunked WAD files are decompressed via Sony's Edge Zlib SPU task queue. Because upstream never implemented this HLE intercept, asset decompression stalled permanently.
2. **SPU PIC ABI & Incomplete Relocation Mechanics:** Upstream v0.19.0 adopted relocatable SPU lifting via commit `b3bfd018` (PR #634), but renamed the API to `spu_overlay_register_region_reloc` and the context field to `reloc_delta`. Our 47 lifted position-independent code (PIC) fragments generated by `tools/lift_spu_pic.py` relied on `spu_overlay_register_pic` and `ctx->pic_delta`. Furthermore, upstream lacks content-based signature matching (`spu_pic_claim`), causing SPU jobs loaded via composite GETs (e.g. module 207 in the main menu) to drop to the interpreter at 230 ms/job (1 FPS).
3. **Missing System & Runtime Hardening Patches:** Upstream lacks our 10 GB free-space floor in `cellGame.c`/`cellSaveData.c` (risking fatal `NOSPACE_EXIT`), the `/dev_hdd1` `ENOENT` stub (causing FIOS scratch cache corruption), per-context `sn_defer` (causing multi-SPU stall-and-notify race conditions), the SPU shadow return stack (causing fatal `spu_halt` on deep call recursions), and host wide window title support.

## 2. Technical Root Cause: Why GAME.PSARC Did Not Decompress Under v0.19.0

### 2.1 The Asset Streaming Pipeline in God of War: Ascension
God of War: Ascension packages all game resources (boot sequences, fonts, textures, shaders, havok collision meshes, level geometry) into `vfs/PS3_GAME/USRDIR/GAME.PSARC` and internal chunked WAD streams. The game engine uses Sony's proprietary **Edge Zlib** middleware:
1. The PPU file streamer reads compressed chunks from the optical disc / VFS (`/dev_bdvd/PS3_GAME/USRDIR/GAME.PSARC`).
2. To decompress each chunk, the PPU initializes a lock-free queue (`CellSpursLFQueue`) and invokes `_cellSpursLFQueuePushBody` (NID `0x8A85674D`) to push a 32-byte work element to the Edge Zlib SPU decompression task.
3. The PPU thread then polls a busy counter in memory (or waits on a `CellSpursEventFlag`) until the decompression task completes.

### 2.2 The 32-Byte Queue Element Structure
As documented in our local `libs/spurs/cellSpurs.c:3973-3983`, the big-endian work descriptor passed to `_cellSpursLFQueuePushBody` contains:
- `+0x00`: `src` (guest EA of compressed data past the 2-byte zlib header)
- `+0x04`: `dst` (guest EA of destination buffer)
- `+0x08`: `srclen` (compressed stream size)
- `+0x0C`: `cap` (maximum output buffer capacity)
- `+0x10`: `counter` (guest EA of the request's completion counter, low bits masked out via `& ~3u`)
- `+0x14`: `flag` (guest EA of `CellSpursEventFlag`)
- `+0x18`: `bits` (event flag bitmask in the upper 16 bits)
- `+0x24`: `skip` (number of leading uncompressed bytes to discard)

The `skip` parameter is critical: GoW:A streams compressed files in pieces. Every chunk request inflates from the start of the same stream, discards the first `skip` bytes, and copies the next `cap` bytes into the destination buffer (e.g. reading a 64-byte WAD chunk header, then payload, then subsequent headers).

### 2.3 Local Implementation in Old Pinned Tree (`9562c751`)
In our local tree, Edge Zlib decompression is intercepted entirely on the host CPU via HLE:
- **`libs/spurs/cellSpurs.c:3967-4025`** (introduced in commit `9afd0618`, modified in commit `e722ac07`):
  When environment variable `PS3_EDGE_ZLIB_HLE` is set (or defaulted on), `_cellSpursLFQueuePushBody` intercepts the push. Instead of placing the item on the SPU ring buffer, it:
  1. Allocates temporary host memory: `malloc(skip + cap)`.
  2. Calls `edge_inflate(buf, skip + cap, vm_base + src, srclen)`.
  3. Copies decompressed bytes past the `skip` offset directly to `vm_base + dst`:
     ```c
     const int n = full < 0 ? -1 : full > (int)skip ? full - (int)skip : 0;
     uint8_t* tmp = buf ? buf + skip : NULL;
     if (n > 0) memcpy(vm_base + dst, tmp, (size_t)n);
     ```
  4. Decrements the guest completion counter:
     ```c
     const uint32_t left = vm_read32(counter);
     if (left) vm_write32(counter, left - 1u);
     ```
  5. If `left == 1u`, signals the completion event flag:
     ```c
     if (left == 1u && flag && bits)
         cellSpursEventFlagSet((CellSpursEventFlag*)(uintptr_t)flag, bits);
     ```
  6. Returns `CELL_OK` immediately without queuing to the SPU.
- **`libs/codec/edge_inflate.cpp:1-248`** (commit `9afd0618`):
  A completely self-contained RFC 1951 DEFLATE / zlib decompressor ported from `sp00nznet/twistedmetal` (`src/tm_inflate.cpp`).
- **`CMakeLists.txt:134`**:
  Links `libs/codec/edge_inflate.cpp` into `ps3recomp_runtime`.

### 2.4 Upstream v0.19.0 Comparison
Grep and `git log -S` across upstream `v0.19.0` (`ae92407b`) and `8c50d9ea` confirm:
- `libs/codec/edge_inflate.cpp`: **DOES NOT EXIST** (`git ls-tree v0.19.0 libs/codec` shows only video/audio codecs: `cellAdec.c`, `cellAtrac.c`, `cellVdec.c`, etc.).
- `PS3_EDGE_ZLIB_HLE`: **DOES NOT EXIST** anywhere in upstream git history.
- `_cellSpursLFQueuePushBody`: Upstream only lists the NID string in `tools/nid_from_protos.json:167` (`"_cellSpursLFQueuePushBody": "0x8A85674D"`). The function has **NO implementation** in `libs/spurs/cellSpurs.c` or anywhere else upstream.
- Result under v0.19.0: Calls to `_cellSpursLFQueuePushBody` either hit an unimplemented NID stub or failed. The 32-byte decompression request was never serviced, the guest completion counter at `counter` was never decremented, and the PPU thread remained blocked forever waiting for `GAME.PSARC` chunks.

## 3. SPU PIC Registration: `reloc_delta` vs `pic_delta`

### 3.1 Overview of SPU Position-Independent Code in GoW:A
In God of War: Ascension, several WWS job modules (notably module 209 and batch job lists) stream up to 3 separate SPU code fragments from the PPU executable (`EBOOT.ELF`) into local store (LS) input buffers. Because fragments are packed back-to-back depending on dynamically calculated buffer sizes, the same binary fragment runs at varying, unaligned LS addresses across different jobs.

Our tool `tools/lift_spu_pic.py` parses `tools/job_fragments.json` (containing **47 distinct code fragments**) and lifts each fragment once at a canonical base address (`0x20000`) using `spu_lifter.py --pic`. The generated registry file `src/gen/spu/pic_register.c` registers all 47 fragments.

### 3.2 Old Pinned Tree Semantics (`9562c751`, Patches 0023 & 0031)
- **API:**
  ```c
  void spu_overlay_register_pic(uint32_t content_ea, uint32_t span, uint32_t lift_base, int image_id)
  ```
  `runtime/spu/spu_channels.c:1816-1823`: Registers `content_ea` and `span`, and stores `s_ovl_src[i].pic_base = lift_base & SPU_LS_MASK;`.
- **Context Field:** `spu_context.h:310` declared:
  ```c
  uint32_t pic_delta;
  ```
- **Dispatch Resolution (`spu_resident_code_fn`):**
  When execution jumps to `pc`, `spu_resident_code_fn` (lines 1880-1920) calculates:
  ```c
  const uint32_t d = ctx->resident_code[slot].lsa - ctx->resident_code[slot].base;
  spu_fn fn = spu_lookup_in_image(pc - d, img);
  if (fn) ctx->pic_delta = d;
  ```
- **Content Matching (`spu_pic_claim`, Patch 0031 `b1f35289`):**
  GoW:A module 207 in the main menu loads code via composite GETs and heap copies that do not start cleanly at `content_ea`. Patch 0031 implemented 64-byte signature hashing (`spu_pic_claim` and `spu_pic_entries_build`). When an interpreter step detects matching bytecode at `pc`, it dynamically marks the fragment resident, allowing it to rejoin lifted execution.

### 3.3 Upstream v0.19.0 Semantics (`b3bfd018` PR #634)
Upstream merged relocatable SPU support independently in commit `b3bfd018`:
- **API:**
  ```c
  void spu_overlay_register_region_reloc(uint32_t content_ea, uint32_t span, uint32_t canon, int image_id)
  ```
  `runtime/spu/spu_channels.c:1974-1985`: `canon` represents the canonical base (e.g. `0x20000`).
- **Context Field:** `spu_context.h:310` declared:
  ```c
  int32_t reloc_delta;
  ```
- **Differences and Regressions in Upstream v0.19.0:**
  1. **Symbol Incompatibility:** Upstream did NOT export `spu_overlay_register_pic`. Linking `src/gen/spu/pic_register.c` against unmodified upstream v0.19.0 resulted in an unresolved external symbol error.
  2. **Field Name Mismatch:** Code lifted by `spu_lifter.py --pic` generated direct accesses to `ctx->pic_delta`. Upstream only declared `ctx->reloc_delta`, causing compilation failure in `src/gen/`.
  3. **No Signature / Content Hashing:** Upstream only marks code resident when an MFC GET exactly hits `content_ea`. For composite GETs (main menu module 207), upstream never identifies the code as resident, forcing continuous fallback to interpreted execution. This increased job execution time from microseconds to ~230 ms per job, reducing main menu performance to ~1 FPS.

### 3.4 The Compatibility Bridge (`2135704d` on `master-gow`)
To bridge the gap between upstream v0.19.0 and our generated PIC code, commit `2135704d` introduced:
1. An anonymous union in `runtime/spu/spu_context.h:310-316`:
   ```c
   union {
       int32_t  reloc_delta;
       uint32_t pic_delta;
   };
   ```
2. A forwarding alias in `runtime/spu/spu_channels.c:1984-1988`:
   ```c
   void spu_overlay_register_pic(uint32_t content_ea, uint32_t span, uint32_t lift_base, int image_id)
   {
       spu_overlay_register_region_reloc(content_ea, span, lift_base, image_id);
   }
   ```
*Note:* While this bridge restores linkage and compilation, it still lacks patch 0031's `spu_pic_claim` signature matching.

## 5. Upgrade & Migration Strategy for Upstream v0.19.0

To safely update `ps3recomp` to upstream v0.19.0 in the future without triggering black screens or performance regressions, the following structured integration plan must be executed:

1. **Retain Local Submodule Branch (`master-gow`):**
   Do not point the submodule directly to upstream release tags (e.g. `origin/master` or `v0.19.0`). Maintain a dedicated integration branch in `ps3recomp` (e.g. `master-gow`) rebased on top of `v0.19.0`.
2. **Cherry-Pick / Re-Apply Critical Port Patches:**
   Before bumping the submodule commit in `CMakeLists.txt`, ensure `master-gow` contains:
   - Patch 0004 + 0006 (`libs/codec/edge_inflate.cpp` and `_cellSpursLFQueuePushBody` HLE in `libs/spurs/cellSpurs.c`).
   - Patch 0056 (10 GB free space floor in `libs/system/cellGame.c` and `cellSaveData.c`).
   - Patch 0059 (`/dev_hdd0` auto-mkdir and `/dev_hdd1` `ENOENT` stub in `runtime/ppu/ppu_fs.cpp`).
   - Patch 0057 (per-context `s_sn_defer_by_id[8]` in `runtime/spu/spu_drain.c` and `spu_dma.h`).
   - Patch 0058 (SPU shadow return stack `spu_drain_frame` in `runtime/spu/spu_drain.c`).
   - Patch 0031 (`spu_pic_claim` signature matching in `runtime/spu/spu_channels.c`).
   - Commit `2135704d` (`pic_delta` union bridge and `spu_overlay_register_pic` alias).
   - Patches 0022 + 0042 (`ld_perf_overlay` in `libs/video/rsx_live_draw.c`).
   - Patches 0030 + 0060 (wide window title APIs in `rsx_host_window.h` and backends).
3. **Verification Gate Before Merging Upstream Bumps:**
   Verify every upstream update using the deterministic check:
   - Run 15-second boot test (`tools/run_harness.ps1 -DurationSec 15`).
   - Confirm in logs:
     1. `[edge] inflate #1 src=...`: confirms Edge Zlib HLE is servicing `GAME.PSARC` requests.
     2. `[cellGame] BootCheck -> free_kb >= 10485760`: confirms 10 GB floor active.
     3. `[fs] open FAIL '/dev_hdd1/cache/' -> ENOENT`: confirms FIOS scratch caching disabled.
     4. `[TELEMETRY 5s] presents > 0`: confirms swapchain presents and visual rendering active.
